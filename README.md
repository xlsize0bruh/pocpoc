# Safari Lock Cookie PoC

Netlify-hosted PoC for checking whether locked Safari restores the previous tab URL and sends cookies before Safari app-lock authentication.

## What changed

The Netlify deployment should serve `/` through `netlify/functions/poc.js` using `netlify.toml` rewrites. The function sends:

```http
Set-Cookie: safari_lock_poc=<value>; Path=/; SameSite=Lax; Secure; Max-Age=86400
Cache-Control: no-store, no-cache, must-revalidate, max-age=0
```

This is stronger than a static page because the cookie is created by a real response header, and the response is marked non-cacheable.

## Test flow

1. Open the Netlify site in Safari on iPhone.
2. Confirm the page says it is generated by a Netlify Function.
3. Tap **Open token URL**.
4. Confirm the page shows `Cookie: safari_lock_poc=...` in the current request block after reload/navigation.
5. Close or background Safari.
6. Turn on Burp intercept.
7. Tap locked Safari but do not pass Face ID.
8. Check whether Burp sees the token URL and `Cookie: safari_lock_poc=...` before Face ID unlock.

Direct function URL:

```text
https://safari-poc.netlify.app/.netlify/functions/poc?para=poc
```

Normal URL after Netlify rewrites deploy:

```text
https://safari-poc.netlify.app/?para=poc
```

## Optional local Node server

If you want local server-side cookie logging too:

```bash
node server.js
```

Then open:

```text
http://<your-computer-ip>:8080/?para=poc
```

The local server prints each request URL and Cookie header.
